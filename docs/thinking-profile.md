## 統合された思考OS（1枚要約）

1. **論点を疑う**：差し出された「正面の問い」は仮の論点。現象/課題/論点を切り分け、真に解くべき論点を選び直す。
2. **仮説を先に置く**：網羅前に「答えはこうでは」を置く。外れてよい、賭けに価値。
3. **発想を揺らす**：反対側・両極端・ゼロベースの3方向で論点/仮説を振る。
4. **ヨコ→タテ**：先に選択肢を拡げ、対象を選んでから深掘る。早すぎる「なぜ？」は局所最適。
5. **具体⇄抽象を往復**：表面を一段抽象化して構造（本質）を掴み、具体の一点に戻す。
6. **アナロジーは構造で**：離れた領域は「構造の共通性」で架ける。表面類似のこじつけは禁止。
7. **結論ファースト＋数字**：言いたいことより伝えるべきこと。冒頭で結論、根拠は数字・事実。
8. **So What?/Why So?**：言い換え止まりと論理の飛びを消す。

## 生成エンジンの中核＝抽象化パイプライン

ニュース投稿の生成は「ニュースの平面の上で気の利いたことを言う」のではなく、
平面を一段上げてから別の場へ降りる三段で行う（`app/api/x-posts/route.ts`）。

1. **essence（具体→本質）**：枝葉を捨て、分野固有語を使わずに「構造的に何の話か」を一文で。
2. **transfer（本質→転用）**：その原理が効く別の場（経営・組織・人・生き方・別ジャンル）を選ぶ。構造の共通性で。
3. **thought（転用→考え）**：そこから書き手自身の主張・問い・予測（外れうる賭け）を立ち上げる。投稿の主役。

| 思考OS | 実装 |
|---|---|
| 具体と抽象の往復・アナロジーは構造で | essence（分野語なしの抽象）→ transfer（構造の共通性で別の場へ） |
| イシュー／論点思考・仮説（外れてよい賭け） | thought＝主張・問い・予測 |
| So What?「で、何を考えるか」 | thought が必須。表面なぞり・感想は禁止 |
| 結論ファースト | hook（1行目で刺す） |
| 数字で語る | post に確認できる数字・具体を一つ |

### 分野は問わない
入力ニュースは経済に限らない。スポーツ・娯楽・社会・事件、何でもよい。
むしろスポーツや娯楽こそ、構造を抽象化して経営・人・生き方へ転用すると効く。分野への感想で終わらせない。

## 文体（声）との関係

思考は上記のとおり鋭く構造的だが、**発話の語尾は柔らかい**（「〜かなと。」「〜と思う。」、短文・句点多め）。
深さ＝思考OS、温度＝文体、の二層で「本人らしさ」を作る。文体見本は生成プロンプト側に同梱。
